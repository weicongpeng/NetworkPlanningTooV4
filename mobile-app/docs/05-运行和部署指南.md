# 运行和部署指南

## 环境要求

### Node.js

- **版本要求**: `>=20.0.0 <22.0.0`
- **检查版本**: `node --version`
- **推荐使用 nvm 管理版本**: `nvm use 20`

### 包管理器

- **npm**: 随 Node.js 一起安装
- **检查版本**: `npm --version`

### Expo CLI

- **安装**: `npm install -g expo-cli`
- **检查版本**: `expo --version`

### Android 环境

- **Android Studio**: 用于 Android 模拟器
- **Android SDK**: API Level 21+ (Android 5.0+)
- **Java JDK**: 11 或更高版本

## 安装依赖

```bash
# 克隆项目
git clone <repository-url>
cd mobile-app

# 安装依赖
npm install
```

## 开发运行

### 启动开发服务器

```bash
npm start
```

启动 Expo 开发服务器，默认监听 `http://localhost:8080`。

### 在 Android 设备/模拟器运行

```bash
npm run android
```

**前提条件:**
1. Android 模拟器已启动，或 Android 设备已连接并开启 USB 调试
2. 设备/模拟器与开发服务器在同一网络

**连接物理设备:**
1. 开启 USB 调试
2. 连接 USB 线
3. 运行 `adb devices` 确认设备已识别
4. 运行 `npm run android`

### 在 iOS 运行（未配置）

```bash
npm run ios
```

**注意**: 项目当前仅配置了 Android 平台，iOS 运行需要额外配置。

## 构建发布

### 构建 Android APK

```bash
npm run build:android
```

此命令会构建 release 版本的 APK。

### 使用 EAS Build

EAS (Expo Application Services) 提供云端构建服务。

#### 安装 EAS CLI

```bash
npm install -g eas-cli
```

#### 登录 Expo 账户

```bash
eas login
```

#### 配置 EAS Build

项目已配置 `eas.json`：

```json
{
  "cli": {
    "version": ">= 3.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "android": { "buildType": "apk" },
      "channel": "development"
    },
    "preview": {
      "distribution": "store",
      "android": { "buildType": "apk" },
      "channel": "preview",
      "env": {
        "EXPO_PUBLIC_API_URL": "https://apk.pengwc.asia"
      }
    }
  }
}
```

#### 构建命令

```bash
# 开发环境构建
eas build --profile development --platform android

# 预览环境构建
eas build --profile preview --platform android
```

#### 查看构建状态

```bash
eas build:list
```

#### 下载构建产物

构建完成后，可以从 Expo 网站下载 APK 文件。

## 环境变量配置

### .env 文件

项目使用 `.env` 文件配置环境变量（已被 `.gitignore` 排除）。

**创建 `.env` 文件:**

```bash
EXPO_PUBLIC_API_URL=https://app.pengwc.asia
```

**变量说明:**

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `EXPO_PUBLIC_API_URL` | 后端 API 地址 | `http://localhost:8000` |

### API 地址解析优先级

应用启动时按以下优先级解析 API 地址：

1. **用户自定义地址**（在设置页面配置，存储到 AsyncStorage）
2. **环境变量** `EXPO_PUBLIC_API_URL`
3. **LAN IP**（从 `Constants.expoConfig.hostUri` 推导）
4. **回退地址** `http://localhost:8000`

所有 API 路径会自动加 `/api/v1` 前缀。

## 权限配置

### Android 权限

项目在 `app.json` 中配置了以下权限：

```json
{
  "android": {
    "permissions": [
      "ACCESS_FINE_LOCATION",
      "ACCESS_COARSE_LOCATION",
      "INTERNET",
      "ACCESS_NETWORK_STATE",
      "READ_EXTERNAL_STORAGE",
      "WRITE_EXTERNAL_STORAGE"
    ]
  }
}
```

**权限说明:**

| 权限 | 用途 |
|------|------|
| `ACCESS_FINE_LOCATION` | 精确 GPS 定位 |
| `ACCESS_COARSE_LOCATION` | 网络定位 |
| `INTERNET` | 网络访问 |
| `ACCESS_NETWORK_STATE` | 检测网络状态 |
| `READ_EXTERNAL_STORAGE` | 读取本地文件 |
| `WRITE_EXTERNAL_STORAGE` | 写入缓存文件 |

### 后台定位

项目配置了后台定位权限（用于导航功能）：

```json
{
  "plugins": [
    [
      "expo-location",
      {
        "locationAlwaysAndWhenInUsePermission": "允许\"工参地图\"在后台获取您的位置以便导航",
        "isAndroidBackgroundLocationEnabled": true
      }
    ]
  ]
}
```

## 缓存系统

### 缓存目录

```
FileSystem.documentDirectory}cache/
├── fullParams/          # 全量工参
│   └── sectors.json
├── geoData/             # 地理化数据
│   └── geo_{id}.json
├── layers/              # 图层文件
│   └── layer_{fid}_{lid}.json
└── meta/                # 元数据（实际用 AsyncStorage）
```

### 首次启动

首次启动时，应用会自动从后端下载全量数据并缓存到本地。

### 手动刷新

在"数据管理"页面可以手动刷新缓存：

1. **全量刷新**: 重新下载所有数据
2. **按类型刷新**: 单独刷新全量工参/地理化数据/图层文件

### 本地导入

支持导入本地文件：

- **Excel**: `.xlsx`, `.xls`
- **CSV**: `.csv`
- **GeoJSON**: `.json`
- **MIF**: `.mif`

**大文件处理:**
- `>5MB` 或 `>5000行`: 流式解析
- `1-5MB`: 异步解析
- `<1MB`: 同步解析

## 常见问题

### 1. 无法连接到开发服务器

**症状:** 设备显示 "Could not connect to development server"

**解决方案:**
1. 确保设备和电脑在同一网络
2. 检查防火墙设置
3. 在设备上手动输入电脑 IP 地址

### 2. Android 构建失败

**症状:** `npm run android` 报错

**解决方案:**
1. 检查 Android SDK 是否安装
2. 检查 Java 版本: `java -version`
3. 清理缓存: `cd android && ./gradlew clean`

### 3. 定位权限被拒绝

**症状:** 无法获取 GPS 位置

**解决方案:**
1. 在应用设置中检查权限
2. 在设备设置中开启位置服务
3. 重新安装应用并授权

### 4. 缓存数据不更新

**症状:** 地图显示旧数据

**解决方案:**
1. 在"数据管理"页面点击刷新
2. 清除应用缓存
3. 重新安装应用

### 5. 大文件导入卡死

**症状:** 导入大文件时应用无响应

**解决方案:**
1. 等待几分钟（大文件需要时间）
2. 如果超过 5 分钟无响应，重启应用
3. 尝试分割文件后分批导入

## 更新策略

### OTA 更新

Expo 支持 OTA (Over-The-Air) 更新，无需重新发布到应用商店。

**发布更新:**

```bash
expo publish
```

**配置更新渠道:**

在 `app.json` 中配置：

```json
{
  "expo": {
    "updates": {
      "url": "https://u.expo.dev/YOUR_PROJECT_ID",
      "enabled": true,
      "checkAutomatically": "ON_LOAD",
      "fallbackToCacheTimeout": 0
    }
  }
}
```

### 强制更新

如果需要强制用户更新，可以在后端 API 返回最低版本号，应用启动时检查并提示更新。

## 安全建议

### 1. API 密钥保护

不要在代码中硬编码 API 密钥，使用环境变量或后端代理。

### 2. HTTPS

生产环境必须使用 HTTPS，避免中间人攻击。

### 3. 输入验证

对所有用户输入进行验证，防止 XSS 和注入攻击。

### 4. 权限最小化

只请求必要的权限，不要过度请求。

### 5. 数据加密

敏感数据（如用户密码）应加密存储。

## 性能优化建议

### 1. 使用聚类

20000+ 点数据时必须使用聚类，避免一次性渲染所有点。

### 2. 视窗过滤

使用 RBush 空间索引只渲染视窗内的点。

### 3. 懒加载

大文件使用流式解析，避免内存溢出。

### 4. 缓存策略

优先读本地缓存，后台刷新。

### 5. 代码分割

使用 React.lazy 和 Suspense 进行代码分割。

### 6. 图片优化

使用 WebP 格式，压缩图片大小。

### 7. 减少重渲染

使用 React.memo 和 useMemo 避免不必要的重渲染。
