# 协作沟通（IM）初步设计方案

> 版本：v1.0（MVP 设计与实施依据）
> 适用：网优引擎 v3.0 · FastAPI + SQLite 单进程 · Vite/React 18 · Web 与桌面共享模式
> 本文是 `/api/v1/im/*` 与前端 `Im` 模块的**唯一接口契约依据**，实现与测试均以此为准。

---

## 1. 目标与边界

### 1.1 功能目标

在应用内提供全局「协作沟通」浮窗：右下角悬浮图标（名字：协作沟通）收集未读消息，点击展开可任意拖动、缩放并置顶的沟通窗口；最小化 / 关闭仅隐藏回图标，会话与草稿不丢失。窗口左侧两个 Tab：

- **消息**：近期聊天列表（个人或群组），含最后一条摘要、时间、未读数。
- **通讯录**：全站用户（区分在线 / 离线）与群组列表（自动数据组群、自建群）。
  > 实现口径修订：后端 `list_contacts` 仍返回全站群并带 `joined` 标记，前端只渲染 `joined=true` 的群；未加入的群不展示、不可点击，避免非成员读消息 404 后落到空态。群成员数以 `im_conversation_members` 真实计数为准，`im_group_meta.member_count` 仅作可自愈的冗余缓存。

会话能力：按 `(地市, 运营商)` 自动建群、允许自建跨组群并管理成员、一对一私聊；消息支持文字、图片、截图、表格文档（xlsx/xls/csv/doc/docx/pdf 等）与其它任意文件。

### 1.2 已确认范围

| 项 | 结论 |
|---|---|
| 通讯录 | **全员可见**，但仅返回身份投影（id、username、is_online、city/operator 标签），不返回业务数据 |
| 私聊 / 自建群 | 允许跨 `(city, operator)` 组 |
| 业务数据隔离 | **不变**。含管理员在内仅可见同组业务数据；IM 不复用 `group_sql_filter`，也不作为绕过业务门禁的通道 |
| 覆盖端 | 网页端 Web（主场景）、Windows 桌面端**共享模式**（在线） |
| 不覆盖 | 桌面单机模式（隐藏入口并提示）、移动端 Expo（仅接口预留） |
| 本期交付 | 初步设计方案 + 网页端可运行 MVP（悬浮窗、文字/图片/文件、群聊私聊、通讯录在线状态、双 Tab 闭环） |
| 后续阶段 | 系统级截屏、超大文件断点续传、离线消息、已读回执、历史搜索、移动端 |

### 1.3 运行环境硬约束

- 生产：Cloudflare Tunnel → `localhost:8000` → systemd `npt-backend.service`，`uvicorn workers=1`（`NPT_WORKERS=1`）。
- 存储：SQLite 单文件 WAL（`data/data.db` 为权威源），**无 Redis / MQ / 对象存储 / Alembic**；`init_db()` 以 `create_all()` + `PRAGMA table_info` 轻量迁移。
- 实时：只有一条 `/api/v1/ws/tasks` WebSocket 通道，后端 `WebSocketManager` 是**单进程内存单例**，无 ack / 序号 / 离线队列；前端重连 2 次失败即降级轮询。
- 桌面：pywebview 壳本机 `127.0.0.1:18789` 起后端，前端 `apiClient` 相对 `/api/v1` **只到本机**；桌面→线上服务器走 HTTP + 签名许可，且**不建 WebSocket**。
- 前端：Tailwind 3.3.6 + 全局 HSL 主题变量，无统一 Modal/Drawer 组件库；`apiClient` 只有默认导出，`chunkedUpload` 未导出。

## 2. 总体架构与关键决策

### 2.1 数据流

```
发送 → REST 事务写 SQLite → send_to_user 轻通知会话成员
     → 各端按 after_id 增量拉取 → 按 message_id 去重合并 → 刷新会话列表与未读角标
WS 断线 / 降级 → 可见窗口低频轮询、桌面共享模式 5s 轮询补偿
附件 → 分片上传落盘 → 生成 ImAttachment → 作为一条 image/file 消息发送
```

**核心决策：SQLite 是唯一真源，WebSocket 只做「有新消息」通知。**
理由：现有 WS 无可靠投递，若把消息正文塞进 WS，断线即丢；REST 游标拉取在单进程下天然幂等、可补偿，且不需要引入 Redis 发布订阅。发送为一次事务写入 + O(m) 轻通知（m = 会话成员数）；增量查询走 `(conversation_id, id)` 索引，复杂度 O(log n + page)。

### 2.2 决策清单

| # | 决策 | 理由 / 权衡 |
|---|---|---|
| 1 | 复用 `/api/v1/ws/tasks` 单连接，只追加 `im_*` 事件 | 避免另建连接的登录/登出/重连分裂；现有 `{"type","taskId","data"}` 外壳不变 |
| 2 | 后端新增 `send_to_user(user_id)` / `send_to_users()` | 现有 `client_user_ids` 只支持排除，没有定向发送 |
| 3 | 建连鉴权兼容增强 | 现有 `websocket.py` 无条件 `accept()`、不校验 jti/空闲超时；MVP 仅让 IM 事件发给 `client_authed` 连接，**不主动断开旧客户端**，避免打断任务进度推送 |
| 4 | 新增独立 `/api/v1/im/contacts` | 现有 `GET /admin/users/` 是管理员专用且桌面端 404，不能给普通用户复用 |
| 5 | IM 可见性由 `ImConversationMember` 判定 | 与 `data_group.group_sql_filter` 完全解耦，业务数据路径零改动 |
| 6 | 附件走 `/api/v1/im/...` blob + `apiClient` | 不挂 `/static`（Vite dev 无代理且无鉴权）；不用 `parallelDownload`（裸 fetch 无 Bearer） |
| 7 | 桌面共享走本机后端透明代理 | 见 §6，前端零改动、无 CORS |
| 8 | 浮窗 `React.lazy` 独立分包 | 首次点击才加载，首屏 chunk 不增加 |

### 2.3 与原方案的差异（实现前复核修正）

原方案设想桌面代理「携带 Ed25519 许可 + 机器码**签名头**」。复核 `desktop_cloud.py::L480 _verify_license(license_file, machine_code, db)` 与 `desktop_cloud_client.py::L79-89` 后确认：**项目没有自定义签名头**，凭证是 JSON body / query / multipart 中的 `license_file` + `machine_code` 两个字段，客户端仅发 `Content-Type` 与 `User-Agent: NPT-Desktop`。因此代理按**字段**传递，见 §6。

## 3. 数据模型（5 张表）

风格沿用现有 ORM：`Integer` 自增主键、`String(30)` ISO 时间、`ForeignKey("users.id")`、复合唯一用 `Index(..., unique=True)`。**全部定义在 `backend/app/models/database.py` 同文件**（`init_db()` 靠导入该模块注册所有类；若拆新文件必须补 import，否则静默不建表）。

| 字段 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | Integer | PK, autoincrement |
| `kind` | String(20) | `direct` / `auto_group` / `custom_group`，not null |
| `group_key` | String(191) | nullable，唯一索引。`direct` = `d:<min_uid>:<max_uid>`；`auto_group` = `g:<city>:<operator>` |
| `name` | String(128) | nullable，群名 |
| `owner_id` | Integer | FK users.id, nullable |
| `city` / `operator` | String(64) | nullable，自动群标签 |
| `last_message_id` | Integer | nullable，冗余加速会话列表 |
| `last_message_at` | String(30) | nullable，ISO 时间，排序用 |
| `created_at` | String(30) | not null |

索引：`Index("idx_im_conv_group_key", "group_key", unique=True)`（SQLite 允许多个 NULL）、`Index("idx_im_conv_last", "last_message_at")`。

|---|---|---|

## 4. REST API 契约

### 4.1 通用约定

- Base：`/api/v1/im`，全部要求 `Authorization: Bearer <JWT>`，走 `Depends(get_current_user)`。
- **响应信封沿用项目现状**：成功 `{"success": true, "data": ...}`；错误由 `HTTPException(status_code, detail=...)` 抛出，FastAPI 返回 `{"detail": "..."}`。
  - 取舍说明：`api-design` 规范推荐 `{"error": {code, message}}`，但全项目 25+ 端点与前端 `apiClient` 拦截器均已按 `success/data` + `detail` 实现，本期**不引入第二套信封**，避免前端分叉。错误码以 `detail` 前缀表达，见 §4.6。
- 资源命名：复数名词、kebab-case、层级表达归属；动作用 `POST /.../<action>`（如 `/read`）。
- 时间：ISO 8601 字符串（UTC）。ID：整数。
- 所有列表端点必须鉴权 + 成员关系校验；非成员一律 **404**（不泄露资源存在性）。

### 4.2 端点总表

| 方法 | 路径 | 说明 | 成功码 |
|---|---|---|---|
| GET | `/conversations` | 近期会话列表 + 批量未读 | 200 |
| POST | `/conversations` | 创建 direct（幂等）或 custom_group | 200 / 201 |
| GET | `/conversations/{id}` | 会话详情 | 200 |
| GET | `/conversations/{id}/members` | 成员列表 | 200 |
| POST | `/conversations/{id}/members` | 加成员（owner/admin） | 201 |
| DELETE | `/conversations/{id}/members/{user_id}` | 移除成员（owner/admin） | 204 |
| GET | `/conversations/{id}/messages` | 游标分页取消息 | 200 |
| POST | `/conversations/{id}/messages` | 发送消息 | 201 |
| POST | `/conversations/{id}/read` | 推进已读游标 | 200 |
| GET | `/contacts` | 全员身份投影 + 在线状态 + 群组列表 | 200 |
| POST | `/groups` | 自建跨组群 | 201 |
| POST | `/attachments/start` | 开始分片上传 | 200 |
| POST | `/attachments/chunk` | 上传分片（body 带 upload_id / chunk_index / data_b64） | 200 |
| POST | `/attachments/complete` | 完成上传，返回 attachment_id | 201 |
| POST | `/attachments/cancel` | 取消上传并清理临时分片 | 204 |
| GET | `/attachments/{id}` | blob 下载（成员鉴权） | 200 |
| GET | `/attachments/{id}/thumb` | 图片缩略图（成员鉴权） | 200 |

### 4.3 请求 / 响应结构

#### `GET /conversations`

```
→ data: {
    items: [{
      id, kind, name, group_key,
      other_user: { id, username, is_online } | null,   // direct 专用
      member_count, last_message: { id, kind, preview, sender_id, created_at } | null,
      last_message_at, unread, muted
    }],
    server_time: "..."
  }
```

排序 `last_message_at DESC`，最多 100 条。`unread` 由成员表 `last_read_message_id` 与会话 `last_message_id` 一次性批量算出，**禁止逐会话 COUNT(*)**。

#### `POST /conversations`

```json
// 单聊（幂等）
{ "kind": "direct", "peer_user_id": 12 }
// 自建群
{ "kind": "custom_group", "name": "XX 项目联调", "member_ids": [3, 7, 12] }
```

- `direct` 用 `group_key = d:<min>:<max>` 唯一索引幂等；重复创建返回已有会话（200）。
- `custom_group` 返回 201 + `Location: /api/v1/im/conversations/{id}`；`member_ids` 上限 `NPT_IM_MAX_MEMBERS_PER_GROUP`，自动补创建者。
- `auto_group` **禁止**由客户端创建。

#### `GET /conversations/{id}/messages`

| 参数 | 类型 | 说明 |
|---|---|---|
| `after_id` | int? | 增量拉取：取 `id > after_id` 的最早 `limit` 条（升序） |
| `before_id` | int? | 上拉历史：取 `id < before_id` 的最新 `limit` 条（升序返回） |
| `limit` | int | 默认 `NPT_IM_MESSAGE_PAGE_SIZE`(30)，范围 1–100 |

二者互斥；都不传=取最新一页。

```
→ data: {
    items: [{ id, conversation_id, sender_id, sender_name, kind, content_text,
              attachment: { id, original_name, mime, size_bytes, has_thumb } | null,
              client_msg_id, created_at }],
    has_more: bool,
    next_cursor: int | null,   // 供下一轮 after_id
    prev_cursor: int | null    // 供下一轮 before_id
  }
```

#### `POST /conversations/{id}/messages`

```json
{ "kind": "text", "content_text": "..." }
{ "kind": "image", "attachment_id": 45, "client_msg_id": "c-..." }
{ "kind": "file",  "attachment_id": 46, "client_msg_id": "c-..." }
```

- `client_msg_id` 可选；重复提交返回首次结果（200 而非 201），由 `(conversation_id, sender_id, client_msg_id)` 唯一索引保证幂等。
- `text` 与 `content_text` 必填且 ≤ 8000 字；`image/file` 必须带 `attachment_id`，且该附件属于本会话、由当前用户上传、未被其它消息占用。
- 成功后事务内更新 `last_message_id/last_message_at`，再对成员（除发送者）推 `im_message` 轻通知。

#### `POST /conversations/{id}/read`

```json
{ "last_read_message_id": 123 }
```

只推进不回退；返回 `{"unread": 0}`。前端在窗口可见且停留该会话时调用。

#### `GET /contacts`

```
→ data: {
    users: [{ id, username, is_online, city, operator }],   // 全站，仅身份投影
    groups: [{ id, kind, name, member_count, is_auto, city, operator }],
    online_count: 8,
    server_time: "..."
  }
```

- 在线判定复用 `auth_service.is_user_online()`（5 分钟窗口）+ `presence_service` 事件；页面隐藏时心跳暂停属既有行为，不改变。
- **只查 `users` 与 IM 表，绝不 join 业务表**。
- 前端每 4 个轮询 tick（网页约 60s / 桌面共享约 20s）批量校准一次，配合 WS `im_presence` 即时更新。

#### 附件上传（三步，与现有分片语义一致）

```
POST /attachments/start      { conversation_id, original_name, mime, size_bytes }
  → { upload_id, chunk_size: 524288, total_chunks }
POST /attachments/chunk      { upload_id, chunk_index, data_b64 }
  → { received: n, total_chunks }
POST /attachments/complete   { upload_id }
  → { id: <attachment_id>, original_name, mime, size_bytes, has_thumb }
POST /attachments/cancel     { upload_id } → 204
```

- 分片以 **base64 放在 JSON body** 而非 multipart：桌面共享模式经 relay 转发时可直接复用同一套 op 白名单，无需额外处理二进制流。网页端上限 `NPT_IM_MAX_FILE_MB`(20MB)，桌面共享因 base64 膨胀与内存占用限 5MB。
- 校验：文件名清洗（去路径分隔与控制字符）、UUID 重命名、大小上限、扩展名/MIME 白名单（拒绝 `.exe/.bat/.sh/.js/.html/.svg` 等可执行/脚本类型）、`storage_path` 禁止 `..` 与绝对路径。
- 落盘：`NPT_IM_ATTACHMENT_DIR/<conversation_id>/<uuid>.<ext>`；图片（Pillow 可用时）生成 320px 缩略图。
- 会话存在即校验成员；上传会话缓存在进程内存（与现有 `_chunked_sessions` 一致），重启后残留由启动清理扫描处理。

### 4.4 WebSocket 追加事件

保持现有外壳 `{"type", "taskId", "data", "timestamp"}`；**`taskId` 必填**（前端 `WebSocketMessage.taskId` 非可选，IM 事件填空串），`type` 追加到前端联合类型。

| type | data | 触发 |
|---|---|---|
| `im_message` | `{ conversation_id, message_id, sender_id, kind }` | 新消息落库后，发给会话成员（排除发送者） |
| `im_unread` | `{ conversation_id, unread }` | **MVP 未启用**：未读由前端从会话列表本地推导，保留事件位供后续扩展 |
| `im_presence` | `{ user_id, online }` | 上线 / 最后一个连接断开 |

前端收到 `im_message` 只做两件事：以 `after_id` 拉取增量、按 `message_id` 去重合并；**不从 WS 取消息正文**。前端重连成功后主动补拉一次。

### 4.5 幂等、限流与状态规范

| 场景 | 规范 |
|---|---|
| 创建 direct | 天然幂等（`group_key` 唯一），重复返回 200 + 已有资源 |
| 发送消息 | `client_msg_id` 幂等，重复返回 200 + 首次消息 |
| 推进已读 | `MAX(last_read_message_id, 传入值)`，幂等 |
| 限流 | 单进程内存滑动窗口：发送 60/min/用户，建群 10/min/用户，附件 start 20/min/用户，`/contacts` 30/min/用户；超限 429 + `Retry-After` |
| 创建成功 | 201 + `Location` 头；重复命中幂等返回 200 |
| 删除成功 | 204 无 body |
| 校验失败 | 422（Pydantic）/ 400（业务规则不合法） |
| 非成员 | 404（不泄露存在性）；权限不足 403 |

### 4.6 错误码（`detail` 前缀）

| HTTP | detail | 含义 |
|---|---|---|
| 400 | `IM_INVALID_PEER` | 单聊对象不存在 / 是自己 |
| 400 | `IM_INVALID_MEMBERS` | 成员为空、超上限、含无效用户 |
| 400 | `IM_ATTACHMENT_TYPE` | 扩展名 / MIME 不允许 |
| 400 | `IM_ATTACHMENT_TOO_LARGE` | 超过 `NPT_IM_MAX_FILE_MB` |
| 400 | `IM_ATTACHMENT_MISMATCH` | 附件不属于本会话 / 已被占用 |
| 403 | `IM_NOT_ADMIN` | 非 owner/admin 操作成员 |
| 404 | `IM_CONVERSATION_NOT_FOUND` | 会话不存在或当前用户非成员 |
| 404 | `IM_ATTACHMENT_NOT_FOUND` | 附件不存在或无权访问 |
| 409 | `IM_UPLOAD_CONFLICT` | 分片序号 / upload_id 冲突 |
| 429 | `IM_RATE_LIMITED` | 触发限流 |
| 502 | `IM_RELAY_FAILED` | 桌面代理转发线上服务器失败 |

日志只记 `conversation_id` / `message_id` / 错误码，不记消息正文；高频轮询不逐条打日志。

- 坐标与导出：图片显示尺寸由 `<img onLoad>` + `ResizeObserver` 维护，裁剪框、文字框、马赛克预览共用一套换算；标注坐标统一按原图像素记录，导出先在整图 canvas 上合成「原图 → 马赛克笔画 → 其它标注」，再按裁剪框复制到输出 canvas，避免 DPI / 窗口缩放 / 最大化造成错位。文字输入用 `preventDefault` + effect 聚焦，避免 pointerup 抢焦点导致空 `blur` 把输入框销毁。

- 截图的安全上下文约束：`getDisplayMedia`、`clipboard.read/write` 只在 HTTPS / localhost 可用；`http://<非 localhost IP>` 下浏览器直接隐藏 `navigator.mediaDevices`，前端按 `window.isSecureContext` 检测并给出可操作的三条降级路径——HTTPS 入口、系统快捷键截图后 `Ctrl+V` 粘贴（paste 事件不受安全上下文限制）、选择图片文件，三者都能进入同一套标注 / 裁剪流程；桌面端 127.0.0.1 属安全上下文，WebView2 未实现接口时同样降级。不承诺系统级截屏，也不枚举系统窗口（网页端无此能力）。

## 6. 桌面共享模式接入

### 6.1 问题

桌面壳内前端 `apiClient` 的 `/api/v1` 指向本机 `127.0.0.1:18789`，若 IM 只落本机 `data.db`，消息无法到达其它用户；桌面端也不与线上服务器建立 WebSocket。

### 6.2 方案：本机后端透明代理

```
桌面前端 imApi (相对 /api/v1/im/*，零改动)
  → 本机 endpoints/im.py 检测 settings.NPT_DESKTOP 且 profile=shared
  → im_desktop_proxy 用 httpx.AsyncClient 转发到
       {NPT_SERVER_URL}/api/v1/desktop-cloud/im/relay
       字段：license_file, machine_code, method, path, query, body
  → 线上 desktop_cloud.py 复用 _verify_license(license_file, machine_code, db)
       从 DesktopLicense 绑定账号解析真实 user（忽略客户端自报 user_id）
  → 调用同一 im_service / im_attachment_service
```

- **凭证传递按项目现状用字段，不是自定义 header**（见 §2.3）：`license_file` 为签名许可全文（`desktop_cloud_client._license_file_text()`），`machine_code` 为 `get_machine_code()`。
- 前端零改动、无 CORS、许可私钥不外泄；线上 relay 只接受白名单内的 IM 路径与方法，防止被当作通用代理。
- 两端共用 `services/im_ops.py` 的 **16 个 op 白名单**：网页端本机端点直接 `run_local_op`，桌面共享经 relay 也走同一分发，线上永远不会被当作通用 HTTP 代理；`attachment_download` 在 relay 上以 base64 返回二进制。
- 桌面 WS 不通线上：`ImHost` 按 `desktopMode` 传 5000ms（桌面共享）/ 15000ms（网页）给 `startPolling`，以 `after_id` 游标增量轮询兜底（与 `desktopSyncStore` 同款节奏），仅在文档可见且窗口展开时执行；`NPT_IM_DESKTOP_POLL_MS` 为服务端预留配置。
- 单机模式（`DESKTOP_PROFILE == 'standalone'` 或服务器探测失败）：`ImHost` 隐藏入口并提示「需共享模式联网」；relay 端点在服务器侧始终可用，桌面本机代理仅在 shared 生效。

## 7. 安全边界

1. **业务数据隔离不变**：`data_group.py` / `core/data_access.py` 零改动；IM 不查询任何业务表。
2. **用户目录可见 ≠ 数据可见**：`/contacts` 只返回 `id/username/is_online/city/operator`；`is_admin`、`license_expiry`、权限位、IP、会话信息一律不返回。
3. **会话/消息/附件鉴权**：所有读写先查 `im_conversation_members`；非成员 404。附件下载必须校验附件所属会话与当前用户成员关系。
4. **文件安全**：UUID 重命名、清洗文件名、白名单 MIME/扩展名、拒绝路径穿越、大小上限、不落可执行脚本；下载用 `Content-Disposition: attachment` 并对图片预览设置 `X-Content-Type-Options: nosniff`。
5. **WS 鉴权**：IM 事件只发给 `client_authed` 连接；不主动断开旧客户端以兼容任务推送。
6. **桌面代理**：线上从许可解析真实用户，忽略客户端自报身份；relay 路径白名单；超时/失败降级 502 `IM_RELAY_FAILED`。
7. **日志与隐私**：不记消息正文、不记附件内容；仅 conversation_id / message_id / 错误码。
